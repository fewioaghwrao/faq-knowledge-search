## 1. テーマ・対象ナレッジ領域

本システムが対象とするナレッジ領域は、**社内業務アプリの操作手順・障害対応ナレッジ** とする。

対象とするFAQ例は以下である。

- ログインできない場合の対応
- 権限エラーが表示された場合の確認手順
- CSV取込エラーへの対応
- PDF出力失敗時の確認手順
- APIエラー・タイムアウト時の一次対応
- 月次処理・締め処理の操作手順
- メール通知が届かない場合の確認手順
- 業務アプリの登録・更新・検索操作に関する問い合わせ

本システムでは、これらのFAQ、手順、障害対応メモを登録し、通常FAQ検索およびAI FAQ検索から必要な情報を確認できることを目的とする。

## 2. プロジェクト概要

### 2.1 背景

社内業務では、操作手順や障害対応方法が、担当者の経験、チャット履歴、個別メモ、手順書などに分散しやすい。

その結果、以下のような課題が発生する。

| 課題 | 内容 |
|---|---|
| 情報が探しにくい | FAQや手順書が分散し、必要な情報にたどり着くまで時間がかかる |
| 属人化しやすい | 対応方法を知っている担当者に確認が集中する |
| 同じ問い合わせが繰り返される | よくある質問がナレッジ化されず、対応コストが増える |
| 新人・引き継ぎ時に困る | 過去対応や業務手順を体系的に確認しづらい |
| AI回答の根拠が不明になりやすい | AIだけの回答では、どのFAQを根拠にしたか確認しづらい |

---

### 2.2 目的

本システムの目的は、社内FAQ・業務ナレッジを一元管理し、担当者が必要な情報をすばやく検索・確認できるようにすることである。

また、AI検索では、登録済みFAQを根拠にした回答を生成し、回答の参照元FAQを表示することで、AI回答の説明可能性を高める。

---

### 2.3 ASP.NET Web Forms版の位置付け

本Web Forms版は、同一テーマのNext.js + ASP.NET Core Web API版と業務要件を共通化しつつ、以下を確認するための比較実装である。

- ASP.NET Web Formsによるサーバーサイド一体型Webアプリケーション
- ASPX、CodeBehind、Master Page、UserControlを利用した画面構築
- ASP.NET Identity 2とOWIN Cookie認証による認証・認可
- Service、DTO、Entity、DbContextによる責務分離
- Entity Framework 6によるMySQLアクセス
- Web Forms環境からのOpenAI API連携
- レガシー技術を利用しながら保守性を考慮した構成

本Web Forms版はローカル実行を対象とし、公開デモ環境は設けない。公開デモは、運用・保守対象の重複を避けるため、同一テーマのNext.js + ASP.NET Core版へ集約する。

公開デモ：<https://faq-knowledge-search.vercel.app/>

### 2.4 システム概要

本システムは、以下の機能を持つWebアプリケーションである。

- FAQ一覧表示

- GitHub ActionsによるCI

## 3. 想定利用者

### 3.1 一般利用者

| 利用者 | 主な使い方 |
|---|---|
| 経理担当者 | 請求処理、CSV取込、月次締めの手順を確認する |
| カスタマーサポート担当者 | 顧客問い合わせに対してFAQを検索し、対応内容を確認する |
| 社内ヘルプデスク | ログイン障害、権限エラー、PDF出力不具合の対応手順を探す |
| 業務システム運用担当者 | API障害、取込エラー、エラーパターンの過去対応を確認する |
| 新人・引き継ぎ担当者 | 業務手順や障害対応メモを学習する |

一般利用者は、公開中かつ未削除のFAQ検索・閲覧、およびAI FAQ検索を利用できる。

---

### 3.2 管理者

| 利用者 | 主な使い方 |
|---|---|
| FAQ管理者 | FAQの登録、編集、論理削除、公開 / 非公開管理を行う |
| システム管理者 | ユーザー状態管理、AI検索履歴確認、FAQ改善の確認を行う |

管理者向け画面は、ASP.NET Identity 2による認証と管理者ロールによる認可を必要とする。

### 4.1 技術構成

| 区分 | 内容 |
|---|---|
| 言語 | C# |

| ORM | Entity Framework 6 |

| Authorization | Adminロール / 管理画面共通基底ページ |
| AI | OpenAI API |
| UI | Bootstrap 5 / jQuery |
| ローカル実行 | Visual Studio 2022 / IIS Express |
| DB実行環境 | Docker / MySQL |
| CI | GitHub Actions |

---

### 4.2 全体構成

```text
[User Browser]
      |
      | HTTP / PostBack
      v
[ASP.NET Web Forms]
      |
      | ASPX / CodeBehind
      v
[Service / DTO]
      |
      | Entity Framework 6
      v
[MySQL Database]

AI検索時：

[AI Search Service]
      |
      | HTTPS
      v
[OpenAI API]
```

---

### 4.3 アプリケーション内の責務分離

```text
ASPX
  ↓
CodeBehind
  ↓
Service
  ↓
DTO / Entity
  ↓
DbContext
  ↓
MySQL
```

| 層・要素 | 主な責務 |
|---|---|
| ASPX | 画面レイアウト、入力項目、サーバーコントロールの定義 |
| CodeBehind | ページライフサイクル、イベント処理、Service呼び出し、画面表示制御 |
| Service | FAQ検索、FAQ更新、AI検索、履歴保存、ユーザー状態管理などの業務処理 |
| DTO | 画面とService間で受け渡す表示・入力データ |
| Entity | DB永続化対象のデータモデル |
| DbContext | Entity Framework 6によるデータアクセス |
| Identity | ユーザー、ロール、認証Cookieの管理 |

## 6. 前提条件・制約

| 項目 | 内容 |
|---|---|
| データ | 実案件情報・機密情報は含めず、ポートフォリオ用のダミーデータを使用する |
| 実行環境 | Windows、Visual Studio 2022、IIS Expressを想定する |
| 認証 | 管理者向け機能はASP.NET Identity 2とOWIN Cookie認証を利用する |
| 認可 | 管理画面はAdminロールを持つ認証済みユーザーのみ利用可能とする |
| AI | OpenAI APIを利用し、FAQコンテキストに基づく回答を生成する |
| AI安全性 | FAQにない内容を断言しないようにプロンプトで制御する |
| DB | MySQL 8を利用する |
| ORM | Entity Framework 6を利用する |
| ブラウザ | Chrome / Edgeの最新版を想定する |
| 公開 | Web Forms版はローカル実行を対象とし、公開デモ環境を設けない |
| APIキー | Git管理対象外の外部設定ファイル等で管理する |
| 接続文字列 | Git管理対象外の外部設定ファイル等で管理する |
| 個人情報 | 実在の個人情報、顧客情報、認証情報を登録しない |
| デモ認証情報 | READMEおよびリポジトリへ掲載しない |

## 7. 用語定義

| 用語 | 定義 |
|---|---|
| FAQ | よくある質問と回答のセット |
| カテゴリ | FAQを業務領域で分類するグループ |
| タグ | FAQに付与するキーワードラベル |
| 公開 / 非公開 | FAQを一般利用者の検索結果へ表示するかを示す状態 |
| 論理削除 | レコードを物理削除せず、削除フラグで非表示にする方式 |
| AI FAQ検索 | 関連FAQを検索し、その内容をAIへ渡して回答を生成する機能 |
| RAG | 検索結果をAIのコンテキストとして利用し、回答を生成する構成 |
| 参照元FAQ | AI回答の根拠として利用したFAQ |
| AI検索履歴 | AI検索の質問、回答、参照元、成否、実行日時を保存した履歴 |
| AI回答フィードバック | AI回答に対する「役に立った / 役に立たなかった」と任意コメント |
| ApplicationUser | ASP.NET Identity 2のユーザーを拡張したアプリケーションユーザー |
| OWIN Cookie認証 | 認証成功後のログイン状態をCookieで維持する認証方式 |
| Admin | 管理者ロール |
| User | 一般ユーザーロール |
| PostBack | Web Forms画面から同一ページへ送信し、サーバー側イベントを実行する仕組み |
| CodeBehind | ASPX画面に対応するC#のサーバー側処理 |

## 9. 機能詳細

| 項目 | 内容 |
|---|---|
| 概要 | 登録済みFAQを一覧表示し、キーワードで絞り込む |

| 一般利用者条件 | `is_published = true` かつ `is_deleted = false` |
| 管理者条件 | 公開・非公開を含む未削除FAQを表示する |
| 一覧制御 | ページネーションを利用する |

|---|---|

| 一般利用者条件 | 公開済みかつ未削除のFAQのみ閲覧可能 |

### 9.3 FAQ登録・編集・論理削除

|---|---|
| 概要 | 管理者がFAQを登録・編集・論理削除する |
| 利用者 | Adminロールを持つ管理者 |
| 入力項目 | 質問、回答、カテゴリ、タグ、公開状態 |
| 削除方式 | `is_deleted`を利用した論理削除 |
| バリデーション | 質問必須、回答必須、カテゴリ必須 |
| タグ | 複数選択可能 |

---

### 9.4 AI FAQ検索

| 項目 | 内容 |
|---|---|
| 概要 | ユーザーの質問に対し、関連FAQを検索してAI回答を生成する |
| 利用者 | 一般利用者、管理者 |
| 入力項目 | 質問文 |
| 検索対象 | 公開済みかつ未削除のFAQ |
| 処理 | 質問文から関連FAQを検索し、上位FAQをAIコンテキストとして利用する |
| 外部連携 | OpenAI API |
| 出力 | AI回答、注意文、参照元FAQ |
| FAQ0件時 | AI回答を生成せず、該当FAQがない旨を表示する |
| 失敗時 | エラー内容を画面向けに整形し、失敗履歴を保存する |

| 目的 | AI回答の根拠を利用者と管理者が確認できるようにする |

### 9.6 AI検索履歴管理

| 項目 | 内容 |
|---|---|
| 概要 | AI検索の実行履歴を保存し、管理画面で確認する |
| 保存項目 | 質問文、検索キーワード、AI回答、参照元FAQ、成否、エラー内容、実行日時 |
| 一覧 | 管理者が履歴を検索・一覧表示する |
| 詳細 | 個別履歴の質問、回答、参照元FAQ、フィードバックを表示する |
| 成功・失敗 | AI検索に失敗した場合も履歴として保存する |

## 13. 非機能要件

### 13.1 パフォーマンス

| 項目 | 要件 |
|---|---|
| FAQ検索 | 通常利用時に数秒以内で検索結果を表示することを目標とする |
| 一覧表示 | ページネーションを利用し、必要な件数のみ表示する |
| AI検索 | 外部API呼び出しを含むためタイムアウトを設定する |
| AIコンテキスト | AIに渡すFAQ件数を必要な上位件数に制限する |
| 重複送信 | AI検索中は多重送信を抑止する |

### 13.2 セキュリティ

| 項目 | 要件 |
|---|---|
| 認証 | ASP.NET Identity 2とOWIN Cookie認証を利用する |
| 管理機能 | Adminロールを持つ認証済みユーザーのみ利用可能とする |
| 管理画面共通制御 | 認可処理を管理画面共通基底ページに集約する |
| 無効ユーザー | `IsActive = false` のユーザーはログイン不可とする |
| パスワード | ASP.NET Identityのハッシュ方式で管理する |
| APIキー | ソースコード、README、Git管理対象ファイルへ記載しない |
| 接続文字列 | ソースコードへ直接記述せず、外部設定として管理する |
| SQLインジェクション対策 | Entity Framework 6またはパラメーター化クエリを利用する |
| XSS対策 | 画面出力時に適切なエンコードを行う |
| オープンリダイレクト対策 | ReturnUrlはローカルURLであることを確認する |
| エラー表示 | 本番想定では例外詳細やスタックトレースを利用者へ表示しない |
| 機密情報 | FAQ、AI回答、履歴、ログへ実在の機密情報を含めない |
| 認証情報 | デモアカウントやパスワードを公開ドキュメントへ掲載しない |

---

### 13.3 AI安全性

| 項目 | 要件 |
|---|---|
| 根拠制御 | 検索したFAQコンテキストに基づく回答に限定する |
| 断言抑制 | FAQにない内容を断言しない |
| 推測抑制 | 手順、原因、担当部署、問い合わせ先を推測で補完しない |
| 参照元表示 | AI回答とあわせて参照元FAQを表示する |
| 個人情報対策 | 個人情報、認証情報、機密情報を出力しない |
| 注意喚起 | 最終判断では参照元FAQの確認を促す |
| 履歴 | 成功・失敗、参照元、フィードバックを保存する |

---

### 13.4 保守性

| 項目 | 要件 |
|---|---|
| 責務分離 | CodeBehindへ業務処理を集中させず、Service・DTOへ分離する |

| データアクセス | DbContextを通じてデータアクセス方法を統一する |

| CI | GitHub Actionsでビルド・テストを自動実行する |

| 設定 | 接続文字列・AI設定を外部設定へ分離する |
| ドキュメント | README、要件定義書、設計書、ER図、画面遷移図を整備する |

## 18. 補足

本書は、ASP.NET Core版で整理した業務要件を基礎としながら、ASP.NET Web Forms版の現行実装に合わせて以下を変更している。

- Next.js + ASP.NET Core Web APIの分離型構成から、ASP.NET Web Formsの一体型構成へ変更
- Entity Framework CoreからEntity Framework 6へ変更
- JWT認証からASP.NET Identity 2 + OWIN Cookie認証へ変更
- REST API要件をASPXイベント・Service要件へ変更
- Next.js形式のURLをWeb FormsのASPX URLへ変更
- フロントエンド・バックエンドテストをService層ユニットテストと手動E2E確認へ変更
- Azure Static Web Apps / Herokuへのデプロイを対象外とし、ローカル実行へ変更
- Web Forms版の実テーブル名とAIフィードバック分離テーブルを反映
- ユーザーロール変更を未実装機能として整理

本Web Forms版では、**ASP.NET Web Forms / .NET Framework 4.8 / Entity Framework 6 / MySQL / ASP.NET Identity 2 / OWIN Cookie認証 / OpenAI API / AI検索履歴 / ユーザー管理 / ユニットテスト / CI** を中心に要件を整理する。
